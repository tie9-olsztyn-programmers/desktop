Wyskakujące okienko

Podstawowe pojęcia​

  • Interaction<TInput, TOutput> kanał komunikacji ViewModel -> View
  • ReactiveCommand logika sterująca akcją użytkownika (przycisk)
  • WhenAnyValue(...) obserwuje zmiany właściwości
  • Select(...) przekształca dane w bool dla canExecute
  • canExecute Zasada bezpieczeństwa:
    • pozwala kliknąć tylko wtedy, gdy
    • warunek (np. Name niepuste) jest spełniony
  • CreateFromTask(...) tworzy komendę asynchroniczną
  • Handle(this) wysyła prośbę od ViewModel do View, przekazując dane
  • RegisterHandler(...) View definiuje, jak ma zareagować na prośbę

Cel​

Do projeku z poprzedniej lekcji dodamy Button podsumowujący wszystkie dane:

  • pobierze wszystkie dane z formularza
  • przekaże je do nowego okna
  • jeżeli pole TextBox będzie puste, przycisk będzie dezaktywowany.

Konfiguracja MainWindowViewModel​

Dodajemy dwie nowe właściwości​

    public ReactiveCommand<Unit, Unit> ShowSummaryCommand { get; }
    public Interaction<MainWindowViewModel, Unit> ShowSummaryWindow { get; }
  • ReactiveCommand jak już wiemy służy do definiowania działania
  • Interaction<TInput, TOutput> to nowe pojęcie
Interaction<TInput, TOutput>

To reaktywny kanał komunikacji między ViewModel’em a View, który:

  • pozwala ViewModelowi poprosić widok o wykonanie akcji UI-np:
    • pokazanie okna,
    • dialogu,
    • MessageBoxa,
    • wyboru pliku,
    • ...
    • widok odpowiada, wykonując tę akcję i opcjonalnie zwracając wynik.

Innymi słowy:

  • To „grzeczna prośba” od ViewModelu do View, bez łamania separacji warstw.
W czystym MVVM:

  • ViewModel nie powinien

    • tworzyć okien (new SummaryWindow(), MessageBox,
    • ani niczego, co jest częścią widoku.

  • jednak czasem musi o coś poprosić użytkownika - np:

    • o potwierdzenie,
    • wybór,
    • dane,
    • ...

  • Jak to zrobić bez zależności od UI?

    • właśnie przez Interaction.
Metafora dla Interaction

Wyobraź sobie, że

  • ViewModel to pracownik biurowy,
  • View to sekretarka mająca dostęp do drzwi, telefonu i ekspresu do kawy
  • ViewModel: „Hej, poproszę o dwie kawy”
  • View: „OK, już przynoszę”

czyli Interaction to komunikat przekazany

  • z biura (ViewMmodel)
  • do sekretariatu (View),
  • bez tego komunikatu każdy pracownik musiałby sam wstawać i robić sobię kawę ;)

Nowym właściwościom przypisujemy dane​

W konstruktorze MainWindowViewModel dopiszemy:

    ShowSummaryWindow = new Interaction<MainWindowViewModel, Unit>();
    var canShow = this.WhenAnyValue(x => x.Name)
            .Select(name => !String.IsNullOrWhiteSpace(name));

    ShowSummaryCommand = ReactiveCommand.CreateFromTask(async () =>
    {
        Console.WriteLine("Command executed inside VM");
        await ShowSummaryWindow.Handle(this);
    }, canShow);

ShowSummaryWindow = new Interaction<MainWindowViewModel, Unit>();:​
  • tworzy kanał komunikacyjny między ViewModel a View.
  • Typ Interaction<TInput, TOutput>:
    • TInput = MainWindowViewModel dane przekazywane do widoku (czyli „co pokazać”),
    • TOutput = Unit wynik z widoku (tu: nic nie zwraca, tylko sygnalizuje „zrobione”).
var canShow​
    var canShow = this.WhenAnyValue(x => x.Name)
        .Select(name => !String.IsNullOrWhiteSpace(name))
  • to jest reaktywne wyrażenie, które tworzy obserwowalny warunek CanExecute dla przycisku.
  • this.WhenAnyValue(x => x.Name)
    • obserwuje właściwość Name ViewModelu,
    • za każdym razem, gdy Name się zmieni, ten strumień emituje nową wartość.
  • .Select(...) przekształca wartość tekstu na bool:
    • true jeśli Name nie jest puste,
    • false jeśli puste lub tylko spacje. czyli: canShow to IObservable<bool> informujące, czy przycisk „Show Summary” powinien być aktywny.
ShowSummaryCommand​
ShowSummaryCommand = ReactiveCommand.CreateFromTask(async () =>
{
    Console.WriteLine("Command executed inside VM");
    await ShowSummaryWindow.Handle(this);
}, canShow);

Tworzy reaktywną komendę, która:

  • jest asynchroniczna (CreateFromTask) — czyli może awaitować,
  • wykona się tylko wtedy, gdy canShow emituje true (czyli gdy w polu Name coś wpisano),
  • po kliknięciu przycisku uruchomi kod z wnętrza { ... }.
await ShowSummaryWindow.Handle(this);
  • Handle() wysyła prośbę do widoku:
    • „Hej, obsłuż to Interaction, przekazuję Ci this (czyli siebie — ViewModel)”
    • widok (czyli MainWindow.axaml.cs) powinien zarejestrować ten handler.
Metafory prawie podsumowujące

Wyobraź sobie biuro programistyczne:

  • ViewModel (pracownik)
    • Chce coś zrobić, ale nie ma dostępu do drzwi ani telefonu.
    • To nasza klasa MainWindowViewModel
  • View (sekretarka)
    • Ma dostęp do sprzętu biurowego, potrafi otwierać drzwi, dzwonić, pokazywać okna.
    • To nasza klasa MainWindow
  • WhenAnyValue
    • Sekretarka obserwuje, czy w formularzu „Imię” coś wpisano.
    • Reaguje na zmiany Name.
  • Select
    • Sekretarka ocenia: „Czy pole nie jest puste?” -> może aktywować przycisk
    • Transformuje dane.
  • ReactiveCommand
    • Przycisk dzwonka na biurku, który pozwala wysłać prośbę (kliknięcie przycisku w UI)
    • to nasz ShowSummaryCommand
  • canShow
    • Warunek: dzwonek działa tylko, jeśli imię wpisane IObservable<bool>
  • Interaction
    • Linia telefoniczna z sekretarką
    • To nasz ShowSummaryWindow
  • Handle()
    • Pracownik dzwoni i prosi: „Otwórz drzwi (pokaż okno)”
    • W naszym przypadku to wywołanie await ShowSummaryWindow.Handle(this)
  • RegisterHandler()
    • Sekretarka odbiera i wykonuje prośbę: „OK, otwieram drzwi”
    • Nasz RegisterHandler(async ctx => ...), którego jeszcze nie mamy.
  • Unit.Default
    • Sekretarka odkłada słuchawkę po skończeniu zadania
    • zakończenie Interaction.

Konfiguracje View​

Co robi .CreateFromTask „pod maską”

ReactiveUI opakowuje Twój Task wewnątrz reaktywnego strumienia:

  • subskrybuje jego wynik,
  • dba o anulowanie,
  • emituje wartości (OnNext),
  • pozwala CanExecute działać w trakcie jego wykonywania. czyli:
ReactiveUI automatycznie „streamuje”
asynchroniczne operacje jako obserwowalne sekwencje.

::: tip Metafora

  • .Create to zwykły włącznik światła – naciśniesz i od razu włącza/wyłącza.
  • .CreateFromTask to przycisk windy – wciskasz, ale
    • trzeba chwilę poczekać, aż przyjedzie (asynchronicznie).

Oba działają, tylko jedno wymaga „czekania na wynik”.

:::

Rejestracja handlera​

Wersja z automatyką​

W MainWindow.axaml.cs w konstrukturze dodamy rejestrację handlera:

 public MainWindow()
    {
        InitializeComponent();
        ViewModel = new MainWindowViewModel();

       // var vm = new MainWindowViewModel();
        DataContext = ViewModel;


// TU JEST NOWY KOD PIERWSZA REJESTRACJA HANDLERA
        this.WhenActivated((CompositeDisposable disposables) =>
        {
            ViewModel!.ShowSummaryWindow.RegisterHandler(async interaction =>
                {
                    var win = new SummaryWindow()
                    {
                        DataContext = interaction.Input
                    };

                    await win.ShowDialog(this);
                    interaction.SetOutput(Unit.Default);
                })
                .DisposeWith(disposables);

        });
//...

WYJAŚNIENIA

Co to jest CompositeDisposable disposables
  • To pojemnik na rzeczy do wyrzucenia — taki reaktywny kosz na śmieci.
  • ReactiveUI przekazuje Ci w WhenActivated specjalny obiekt CompositeDisposable.
  • Każdy obiekt, który implementuje IDisposable (np. RegisterHandler, Subscribe,...) możesz „włożyć do kosza” przez .DisposeWith(disposables).
  • Kiedy okno zostanie dezaktywowane (zamknięte), cały ten „kosz” zostanie automatycznie opróżniony.
Co to jest .DisposeWith(disposables)
  • „dodaj ten obiekt do listy rzeczy do posprzątania, gdy okno zniknie”.
  • to skrót dla instrukcji disposables.Add(someSubscription)

::: note Co to robi WhenActivated(...)

  • WhenActivated to metoda dostępna w klasach ReactiveUI, takich jak:

    • ReactiveWindow,
    • ReactiveUserControl,
    • ReactiveContentControl.

  • Jej zadaniem jest

    • zareagowanie, gdy widok zostaje aktywowany (otwarty, pokazany)
    • wykonanie określonego kodu tylko na czas aktywności widoku. czyli

  • this.WhenActivated(disposables => { ... }); - "mówi":

    • „Kiedy ten widok jest aktywny — wykonaj ten kod"
    • Kiedy widok zostanie zamknięty — automatycznie wszystko posprzątaj”

:::

Wersja z ręczną obsługą​

  • Chcąc lepiej zrozumieć powyższy kod, napiszemy tę samą funkcjonalność,

  • jednak ręcznie będziemy o wszystko dbali.

  • Zakomentujmy kod z this.WhenActived.

  • nasze View, czyli MainWindow potrzebuje pola do zapamiętania subskrypcji private IDisposable? _disposable

  • rejestracja handlera w konstruktorze:

public MainWindow()
    {
        InitializeComponent();
        ViewModel = new MainWindowViewModel();

        // var vm = new MainWindowViewModel();
        DataContext = ViewModel;


// (_,_) - to parametry zdarzenia `Opened`
// dokładniej (sender, arge)
        _disposable = null;
        this.Opened += (_, _) =>
        {
            _disposable = ViewModel.ShowSummaryWindow.RegisterHandler(async interaction =>
            {
                var win = new SummaryWindow
                {
                    DataContext = interaction.Input
                };
                await win.ShowDialog(this);
                interaction.SetOutput(Unit.Default);
            });
        };
    }
this.Opened +=
  • zdarzenie Opened:
    • wywoływane raz, gdy okno zostanie w pełni otwarte, załadowane i pokazane na ekranie;
    • używamy go, gdy chcemy mieć pewność, że operacje (np. rejestracja handlera Interaction) wykonają się po załadowaniu interfejsu użytkownika;
    • bez tego zdarzenia rejestracja RegisterHandler(...) może nastąpić zbyt wcześnie:
      • zanim Interaction z ViewModelu będzie gotowe
      • i pojawi się błąd „Failed to find a registration for an Interaction”.
  • składnia += oznacza subskrypcję na zdarzenie (Opened ),
    • czyli: „gdy to zdarzenie wystąpi, wykonaj ten blok kodu”.
  • zapis (_, _) => { ... } to funkcja lambda:
    • jej dwa argumenty (sender, EventArgs) są nieużywane,
    • więc oznaczono je znakiem podkreślenia _
  • handler zarejestrowany, jeszcze czyszczenie pamięci
 protected override void OnClosed(EventArgs e)
    {
        base.OnClosed(e);

        // jeśli subskrypcja istnieje, usuniemy ją z pamięci
        // podobne działania były w Kotlinie przy fragmentach
        _disposable?.Dispose();
        _disposable = null;

    }
