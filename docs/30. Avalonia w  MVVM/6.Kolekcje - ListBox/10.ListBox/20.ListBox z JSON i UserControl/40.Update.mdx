# Aktualizacja - UPDATE


---
## Aktualizacja danych z listy - *UPDATE*
- klikamy na element z  `ListBox`,
- kilkamy na `Edit` `Button` tego elementu,
- pojawia się nowe okno z danymi elementu wybranego
- wprowadzamy zmiany,
- klikamy "Zapisz"
- dodatkowe okienko zamyka się,
- w `ListBox` pojawiają się zaktualizowane dane


### Zmiany w `MainWindow.axaml`
- Do każdego elementu `ListBox` dodamy przycisk do edycji.
- Wyłączymy `CompileBindings`.

```xml
<Window <!-- ... -->
        Title="ListBoxUserControlJSON"

        x:CompileBindings="False"
        >
<!-- ... -->
 <DataTemplate>
    <StackPanel Width="400" Spacing="10">
        <TextBlock Text="{Binding Name}" FontWeight="Bold"/>
        <TextBlock Text="{Binding Role}" FontStyle="Italic"/>
        <TextBlock Text="{Binding Description}"
                   TextWrapping="Wrap"/>

        <Button Content="Edytuj"
                HorizontalAlignment="Left"
                Command="{Binding $parent[Window].DataContext.EditCommand}"
                CommandParameter="{Binding}"
        />
    </StackPanel>
</DataTemplate>
```
- `CommandParameter` przekazuje cały obiekt jako parametr komendy
- problem: `DataContext` dla wybranego elementu ma typ `Character` a `EditCommand` jest w `MainWindowViewModel`
- rozwiązanie:
  - `$parent[Window]` znajdź rodzica typu Window
  - `.DataContext` weź jego `ViewModel`
  - `.EditCommand` weź komendę

## Zmiany w `MainWindowViewModel.axaml.cs`
### Metoda do edycji elementu z listy
Potrzebujemy:
- zmiennej do przechowywania informacji, o tym, który elemenent został wybrany `SelectedCharacter`.
- metody, która pozwoli nam edytować wybrany element `EditCommand`.
```cs
//...
    // właściwość przechowująca wybrany element-obiekt Character
    public Character? SelectedCharacter {get; set;}

    public ReactiveCommand<Unit, Unit> AddCommand { get; }
    public ReactiveCommand<Unit, Unit> SaveCommand { get; }

    // metoda pozwalająca na edycję elementu
    public ReactiveCommand<Character, Unit> EditCommand { get; }

    public MainWindowViewModel()
    {
        LoadCharacters();

        AddCommand = ReactiveCommand.Create(AddCharacters);
        SaveCommand = ReactiveCommand.Create(SaveToJson);

        EditCommand = ReactiveCommand.Create<Character>(OpenEditWindowAsync);


    }


      private async void OpenEditWindowAsync(Character character)
    {
        await new EditWindow
       {
           DataContext = new EditCharacterViewModel(character)
       }.ShowDialog(Application.Current!.GetMainWindow()!);
    }

```
:::tip Co to jest *Application.Current*?
- to statyczna właściwość, która w każdej chwili działania aplikacji zwraca aktualnie uruchomioną instancję klasy Application (czyli całą naszą aplikację Avalonia).
- jest to taki „globalny singleton” – zawsze dostępny z dowolnego miejsca w kodzie.

:::

Aby powyższy kod mógł zadziałać, potrzebujemy  jeszcze metody `GetMainWindow()`.

Dlatego zrobimy nowy folder `Extensions`, a wewnątrz niego plik `AvaloniaExtensions.cs`
```cs
using Avalonia;
using Avalonia.Controls;
using Avalonia.Controls.ApplicationLifetimes;

namespace <tu musi być twoja przestrzeń nazw>

public static class AvaloniaExtensions
{
    public static Window? GetMainWindow(this Application app)
        => (app.ApplicationLifetime as IClassicDesktopStyleApplicationLifetime)?.MainWindow;

}

```

:::tip Klasa statyczna `static class`
- klasa statyczna to klasa, której nie można tworzyć jako obiekt
(nie zrobisz `new AvaloniaExtensions()`).
- zawiera tylko metody statyczne (albo stałe, albo statyczne właściwości).
- służy do trzymania pomocniczych funkcji, które nie należą do żadnego konkretnego obiektu.

:::

:::tip *Expression-bodied method*
`metoda() => coś`

to skrócony zapis:

```cs
metoda()
{
    return coś
}
```

Przykład:
```cs
public int Add(int a, int b)
{
    return a + b;
}
```

w wersji skróconej:
```cs
public int Add(int a, int b) => a + b;
```

:::

:::info Czym jest `this Application app`
- nasza metoda jest `public static`
- jej pierwszym argumentem jest `this`
- czyli ta metoda jest metodą rozszerzającą
- czyli znaczy to samo co:
**"Dodaj tę metodę jako metodę instancyjną do klasy Application"**

czyli zamiast
`AvaloniaExtensions.GetMainWindow(Application.Current)`

będziemy pisać
`AvaloniaExtensions.GetMainWindow(Application.Current)`
:::


**Wyjaśnienie** `(app.ApplicationLifetime as IClassicDesktopStyleApplicationLifetime)?.MainWindow;`
1. `app.ApplicationLifetime`
 - to informacja o tym, jak aplikacja została uruchomiona:
 - na desktopie (Windows/Linux/macOS) -> `IClassicDesktopStyleApplicationLifetime`
 - albo jako `single-view app` (Android, iOS, Web) -> `SingleViewLifetime`
2. `as IClassicDesktopStyleApplicationLifetime`
 - próbujemy zrzutować (`cast`) `ApplicationLifetime` na wersję desktopową.
 - Jeśli aplikacja działa jako desktop:
  - rzutowanie się udaje
  - mamy dostęp do właściwości `.MainWindow`
 - Jeśli to nie jest desktop (np. Android):
  - rzutowanie zwróci `null`
3. `?.MainWindow`  Operator `?.` znaczy:
 - "Jeśli poprzedni obiekt jest nie `null`, to pobierz `MainWindow`"
 - "Jeśli jest `null`, to zwróć `null`"


## Piszemy nowe okno do aktualizacji danych
- prawy klawisz myszy na folderze `View`
- `Add` > `AvaloniaWindow` > nazwijmy `EditWindow`

### `EditWindow`

#### Definiujemy wygląd formularza do aktualizacji
```xml
<!-- ... --->
 Width="400"
        Height="300"
        Title="Edytuj bohatera"
        x:DataType="vm:EditCharacterViewModel"
        >
    <StackPanel Margin="20" Spacing="10">
        <TextBlock Text="Edytuj bohatera" FontSize="18" FontWeight="Bold"/>

        <TextBox Text="{Binding Name}" Watermark="Imię i nazwisko"/>
        <TextBox Text="{Binding Role}" Watermark="Rola"/>
        <TextBox Text="{Binding Description}"
                 Height="80"
                 AcceptsReturn="True"
                 TextWrapping="Wrap"/>

        <StackPanel Orientation="Horizontal" Spacing="10">
            <Button Content="Zapisz" Command="{Binding SaveCommand}"/>
            <Button Content="Anuluj" Command="{Binding CancelCommand}"/>
        </StackPanel>
    </StackPanel>
```
- będziemy musieli dodać `EditCharacterViewModel`
- `x:DataType="vm:EditCharacterViewModel`:
  - To działa tylko w czasie kompilacji i pisania XAML, i jest ogromnym udogodnieniem, które:
  - daje pełne *IntelliSense* (podpowiedzi do `Name`, `Role`, `Description`),
  - wykrywa błędy bindingów na etapie kompilacji (`compiled bindings`),
  - przyspiesza renderowanie UI (kompilator generuje IL(*Intermediate Language*) dla bindingów):
  - .NET działa tak:
  - Kompilujesz C# ->  powstaje IL
  - Dopiero podczas uruchamiania (runtime / JIT) IL jest tłumaczone na kod maszynowy procesora,
  - pozwala Riderowi/VS zrozumieć, jaki typ jest `DataContext`,
  - ale NIE zmienia sposobu działania programu.


#### Definiujemy `EditCharacterViewModel`
1. Aby uprościć pracę, możemy nasz model przekształcić, wprowadzając właściwości reaktywne
```cs
public class Character : ReactiveObject
{
    [Reactive] public string Name { get; set; } = string.Empty;
    [Reactive] public string Role { get; set; } = string.Empty;
    [Reactive] public string Description { get; set; } = string.Empty;
}
```


2. `EditCharacterViewModel`
```cs
public class EditCharacterViewModel : ViewModelBase
{
    private readonly Character _character;

    [Reactive] public string Name { get; set; }
    [Reactive] public string Role { get; set; }
    [Reactive] public string Description { get; set; }

    public ReactiveCommand<Unit, Unit> SaveCommand { get; }
    public ReactiveCommand<Unit, Unit> CancelCommand { get; }

    public EditCharacterViewModel(Character character)
    {
        _character = character;

        Name = character.Name;
        Role = character.Role;
        Description = character.Description;

        var isValid = this.WhenAnyValue(
            x => x.Name,
            x => x.Role,
            x => x.Description,
            (n, r, d) =>
                !string.IsNullOrWhiteSpace(n) &&
                !string.IsNullOrWhiteSpace(r) &&
                !string.IsNullOrWhiteSpace(d)
        );

        SaveCommand = ReactiveCommand.Create(() =>
        {
            _character.Name = Name.Trim();
            _character.Role = Role.Trim();
            _character.Description = Description.Trim();
            CloseWindow();
        }, isValid);

        CancelCommand = ReactiveCommand.Create(CloseWindow);
    }

    private void CloseWindow()
    {
        if (App.Current?.ApplicationLifetime is not IClassicDesktopStyleApplicationLifetime desktop) return;
        desktop.Windows.FirstOrDefault(w => w.DataContext == this)?.Close();
    }
}

```
**Jak `ViewModel` może zamknąć okno (`View`)?**
Zgodnie z MVVM nie może, bo nie "zna" okna.
Stąd nasza specjalna metoda `CloseWindow()`:
```cs
private void CloseWindow()
    {
        if (App.Current?.ApplicationLifetime is not IClassicDesktopStyleApplicationLifetime desktop) return;
        desktop.Windows.FirstOrDefault(w => w.DataContext == this)?.Close();
    }
```
Zobaczmy, co kryje się w tej metodzie:
- `App.Current` to bieżąca instancja aplikacji Avalonia
- `?.` to bezpieczny operator `null`, jeśli `App.Current` jest `null`, cała reszta się nie wykona,
- `ApplicationLifetime` to właściwość mówiąca, w jakim trybie działa aplikacja:
  - desktop,
  - web,
  - mobile
- `is not IClassicDesktopStyleApplicationLifetime desktop`,
jeśli `ApplicationLifetime` nie jest typem klasycznej aplikacji desktopowej, to:
  - przerywamy działanie (`return`)
  - jednocześnie przypisujemy go do zmiennej `desktop`
- `desktop.Windows` to kolekcja wszystkich otwartych okien w aplikacji
- `FirstOrDefault(w => w.DataContext == this)`
  - Szuka pierwszego okna, którego `DataContext` to dokładnie ten `ViewModel` (`this`)
- `?.Close();`:
  - jeśli coś znaleziono, wywołaj `Close()`,
  - jeśli nie, to nic nie rób (`?.` chroni przed `NullReferenceException`)


Nasz kod możemy poprawić wprowadzając pojęcie *serwisu*.
