# Anonymous Functions & Lambdas in C#
Welcome, young Padawan, to the Jedi Archives of C#. Today, we are studying a profound technique in the programming Force:
Anonymous Functions and Lambda Expressions.

:::tip Anonymous functions
They are blocks of code defined without a name. They are incredibly useful when you want to pass a routine as
an argument to another method without the ceremonial overhead of creating a fully declared method.

We will master this using the elegant Lambda Expression (`=>`), a modern, concise, and
syntactically readable way to define anonymous functions. Let's ignite our lightsabers and dive in!

:::

:::info The Power of LINQ: Declarative Pipelines & Efficiency
LINQ (Language Integrated Query) transforms C# data manipulation from imperative (writing complex foreach loops and if statements to tell the computer how to do it) to declarative (chaining methods to tell the computer what you want to achieve).

Pro Tip for Performance: Any() vs. Count()
A very common mistake when learning LINQ is checking for the existence of an item using .Count(). Always use .Any() instead:

Avoid: if (roster.Count(c => c.Alignment == "Dark") > 0)
This forces LINQ to iterate through the entire collection to count every single match before evaluating the > 0 condition.

Use: if (roster.Any(c => c.Alignment == "Dark"))
This is highly optimized. It stops iterating the exact millisecond it finds the very first match. For large datasets or Entity Framework database queries, this simple swap saves significant CPU cycles and memory.
:::

:::tip C# Records: Built for Immutable Data
A record in C# is a special reference type designed specifically for encapsulating data with minimal boilerplate code.

Here is what makes it unique and when you should use it:

Value-based Equality: Unlike a standard class (which compares memory references), two record instances are considered equal if all their properties contain the exact same data.

Immutability by Default: When you use the one-line positional syntax (record Character(...)), C# automatically creates read-only properties. Once created, the object's state cannot be changed.

Non-destructive Mutation: If you need to change a value, you create a new copy with the with expression:
`var strongerLuke = luke with { PowerLevel = 20000 };`

When to use it: Records are perfect for Data Transfer Objects (DTOs), configuration settings, API responses, or any domain models where the data should remain read-only and predictable throughout its lifecycle.
:::

## 2. Deconstructing the Code (The 4w2h Model)
Let's break down the mechanics of our Galactic Archive using the 6 dimensions of the 4w2h model.

0. The Domain: WHAT are we processing?
Metaphor: The Holocron Datacore.Technical: We are processing Complex Objects (our Character records containing multiple properties) and transforming them into Primitives
(like the `int totalPower` or `bool hasSmugglers`). Lambda expressions act as the extraction lens, picking exactly what piece of the object we care about.

1. State & Storage: WHERE does the data live?
- Metaphor: The local ship's computer.Technical: The data lives in Local Variables in memory (`List<Character>`).
The lambda expressions do not alter the database; they evaluate data residing inside the volatile RAM allocated to the `Main`
method.

2. Evaluation Strategies: WHEN do we cook?
- Metaphor: Jedi Reflexes. A Jedi doesn't strike until the exact moment it is necessary.
- Technical: This is the difference between Lazy and Eager paradigms. LINQ methods like Where and Select use Deferred (Lazy) Execution. The lambda c => c.Name isn't actually executed until you iterate over names or call .ToList(). It just builds a query plan. However, methods like FirstOrDefault, Any, and Aggregate are Eager—they force the execution immediately to return a concrete value.

3. Data Flow: WHO sets the pace?
Metaphor: The Force Pull.Technical: We are operating on a Pull Model.
The  `IEnumerable` returned by our LINQ methods sits quietly until a consumer (like a `foreach` `loop` or `.ToList()`) pulls
the data through the lambda expressions one item at a time.



4. Reactivity: HOW does the UI know?
Metaphor: Blind communications.Technical: We are using Plain Variables.
If Darth Vader's power level changes later in the application, the totalPower integer will not automatically update.
There is no Reactive State or Event Bus here; it is a point-in-time calculation.

5. Lifecycle: HOW LONG does it survive?
Metaphor: Force Ghosts. They appear for a moment and then vanish.Technical: The objects and the anonymous functions exist
in Volatile memory. The lambdas are compiled into hidden delegates by the compiler, but the actual data they process is
garbage-collected once the Main method finishes executing.


## 3. Deep Dive: Lambda Syntax and LINQ Arsenal
An anonymous function via lambda uses a very specific syntax. Think of the => operator as a lightsaber.
The hilt is the input parameters, and the blade is the execution logic:

```csharp
// Syntaktyka (Syntax)
(parameters) => expression

// Or for multiple lines:
(parameters) => {
    // code block
    return value;
}
```
Let's review the Jedi tools (LINQ methods) we used in the code:

1. `Where` - Filtering Data
Use this to separate the Light from the Dark.Where takes a condition (a predicate) and returns only
the elements that evaluate to true.
```csharp
var sithLords = roster.Where(c => c.Alignment == "Dark").ToList();
// Result: Only Darth Vader and Emperor Palpatine are returned.
```


2. `Select` - Transforming Data
Use this to mind-trick objects into a new shape.Select maps each element to a new form. It is a projection.
```csharp
var names = roster.Select(c => c.Name);
// Result: A list of purely strings ("Luke Skywalker", "Darth Vader", etc.)
```
:::tip LINQ Deferred Execution
In C#, LINQ methods like Select() use deferred execution. This means the names variable doesn't hold
the actual data in memory yet, but rather the query to retrieve the data.

If you plan to iterate over the results multiple times, or if you need a concrete list right away, append
`.ToList()` or `.ToArray()` to execute the query immediately:

```C#
var namesList = roster.Select(c => c.Name).ToList();
```

:::



3. `OrderBy` / `OrderByDescending` - Sorting Data
Use this to rank the Jedi Council.
Sorts the elements based on a specified key.
```csharp
var sortedNames = roster.OrderBy(c => c.Name); // Alphabetical
var sortedPower = roster.OrderByDescending(c => c.PowerLevel); // Highest to lowest
```

:::tip Return Type of LINQ Sorting
The data type of rankedPower is `IOrderedEnumerable<Character>`.

When you use sorting methods like `OrderBy()` or `OrderByDescending()` in LINQ, they do not just return a standard `IEnumerable<T>`.
Instead, they return an `IOrderedEnumerable<T>`.

Why does this matter?
This specific interface allows you to chain secondary sorting operations using `.ThenBy()` or `.ThenByDescending()`.
For example, if multiple characters had the exact same PowerLevel, you could break the tie by sorting them alphabetically:
```csharp
var rankedPower = roster
    .OrderByDescending(c => c.PowerLevel)
    .ThenBy(c => c.Name);

```

Just like `Select()`, this query uses deferred execution. If you need the sorted result as a concrete list,
you must append `.ToList()` at the very end.
:::





4. `First` / `FirstOrDefault`- The Chosen One
Use this to find a specific target.
Returns the first element that matches the condition. First throws an exception if no match is found
(like a Sith dealing in absolutes).
`FirstOrDefault` safely returns null (or the type's default value) if nothing matches.
```csharp
var grandMaster = roster.FirstOrDefault(c => c.PowerLevel > 17000);
// Result: Yoda
```

5. `Any` / `All` - Scanning the Sector
Use this to check for the presence of enemies.
- `Any`: Returns true if at least one element meets the condition.
- `All`: Returns true if every single element meets the condition.

```csharp
bool hasSmugglers = roster.Any(c => c.Alignment == "Smuggler"); // True (Han Solo)
bool allAreSith = roster.All(c => c.Alignment == "Dark"); // False
```

6. Aggregate - The Power of the Many
Use this to combine the Force.
Reduces a collection to a single value by applying an accumulator function repeatedly.
```csharp
// Aggregate(initialValue, (accumulator, currentElement) => operation)
int totalPower = roster.Aggregate(0, (acc, c) => acc + c.PowerLevel);
// Result: 0 + 15000 + 16000 + 18000 + 100 + 17000 = 66100
```

$$ 4. Summary & Checkpoint
Key Takeaways:
1. Lambdas (`=>`) are a concise way to write anonymous functions.
2. They are heavily utilized in LINQ to manipulate collections via a Pull Model using Lazy Evaluation (until
a terminal operation like `.ToList()` or `.Aggregate()` is called).
3. Methods like `Where` filter, `Select` transform, and `Aggregate` reduce.
