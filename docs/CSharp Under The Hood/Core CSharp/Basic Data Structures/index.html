  • Basic Data Structures - Arrays, Lists, & Dictionaries

🛡️ Welcome, Code Adventurer!

Every hero needs a backpack to carry their loot. In the realm of C#, your loot consists of data (numbers, texts, objects), and your backpacks are called Data Structures.

Today, we will conquer three essential storage dungeons: Arrays, Lists, and Dictionaries.

Grab your keyboard, and let's dive into the code!

🛑 Level 1: Arrays (The Rigid Boxes)​

Let's start with the most fundamental structure. Look at the code below, read it carefully, and try to figure out what it does before scrolling down.

📜 The Top-Down Code​

using System;

public class Program
{
    public static void Main()
    {

        int[] numbers = new int[5];
// inna syntaktyka  var numbers = new int[5];
        numbers[0] = 10;
        numbers[1] = 20;

        Console.WriteLine("Printing the array object: " + numbers);

        string[] names = {"Gieżomin", "Holisława", "Kircika", "Hszźrćw2"};

        Console.WriteLine($"First hero: {names[0]}, Second hero: {names[1]}");

        Console.WriteLine("\n--- Rolling call using for-loop ---");
        for (int i = 0; i < names.Length; i++)
        {
            Console.WriteLine($"Hero at index {i}: {names[i]}");
        }

        Console.WriteLine("\n--- Rolling call using foreach ---");
        foreach(string name in names)
        {
            Console.WriteLine(name);
        }
    }
}
🧠 The Hero's Challenge (Think about it!)
  • Question 1:
    • Look at Console.WriteLine(numbers);.
    • If you run this, it won't print "10, 20".
    • Instead, it prints System.Int32[].
    • Why doesn't C# just print the numbers?
  • Question 2: What would happen if you tried to add a 6th element to numbers[5] = 99;?

🔬 The 4w2h Breakdown​

Let's dissect Arrays using our trusty 4w2h scanner:

0. WHAT are we processing? (Domain)​

  • Metaphor: An egg carton.
  • Definition: A static data structure storing elements of the same type sequentially in memory.
  • Humor: It’s like buying a 6-pack of donuts. You have exactly 6 slots. If you want a 7th donut, you have to throw away the whole box, buy a bigger box, and move the 6 old donuts into it.

1. WHERE does the data live? (State & Storage)​

  • Local memory.
  • The array object lives on the Heap, while the reference (the variable name numbers) lives on the Stack.

2. WHEN do we cook? (Evaluation Strategies)​

  • Eager Paradigm. When you say new int[5], C# immediately allocates memory for 5 integers, even if they are empty (defaulted to 0). It doesn't wait.

3. WHO sets the pace? (Data Flow)​

  • Pull Model. The array just sits there silently.
  • It only gives you data when you explicitly pull it using an index, e.g., names[0].
  1. HOW does the UI know? (Reactivity)
  • Standard Variable. Arrays are entirely oblivious.
  • If you change names[0] = "Bob", the array doesn't broadcast a notification.
  • If a UI is connected to it, it won't update automatically.
  1. HOW LONG does it survive? (Lifecycle)
  • Volatile Memory. It lives only as long as the application is running and the variable is in scope.
  • Once it's abandoned, the Garbage Collector eats it.

🧬 Level 2: Lists (The Elastic Backpacks)​

Arrays are too rigid? Enter Generics. Generics (<T>) allow us to create universal classes that can operate on any data type while keeping strict type-safety. To unlock this magic, you MUST add using System.Collections.Generic; at the top of your file.

📜 The Top-Down Code​

using System;
using System.Collections.Generic; // ⚠️ REQUIRED FOR LISTS & DICTIONARIES! But now it is not obligatory

public class Program
{
    public static void Main()
    {
        List<string> pizzaList = new List<string>();
/* You can write also:
        List<string> pizzaList =
        [
            "Margarita",
            "Capricciosa",
            "Pepperoni",
            "Hawaiian"
        ];
*/

        pizzaList.Add("Margarita");
        pizzaList.Add("Capricciosa");
        pizzaList.Add("Pepperoni");
        pizzaList.Add("Hawaiian");

        Console.WriteLine($"I choose you: {pizzaList[1]}"); // Capricciosa!

        pizzaList.Remove("Pepperoni"); // Goodbye, spicy sausage.

        Console.WriteLine("\nRemaining Pizzas:");
        foreach (string pizza in pizzaList)
        {
            Console.WriteLine(pizza);
        }
    }
}
🧠 The Hero's Challenge

Question: You never told the List how big it should be. How does it know how to store 4 pizzas without throwing the IndexOutOfRangeException we saw in Arrays?

🔬 The 4w2h Breakdown​

0. WHAT are we processing? (Domain)​

  • Metaphor: Hermoine Granger's magical expanding handbag.
  • Definition: A generic, dynamically resizable collection that implements IList<T>.
  • It maintains insertion order.
  • Humor: It's the array's cooler, more successful sibling who actually learned how to adapt to changes in life.

1. WHERE does the data live? (State & Storage)​

  • Local memory (Heap).

2. WHEN do we cook? (Evaluation Strategies)​

  • Eager insertion, but Lazy expansion.
  • It only resizes its internal storage when absolutely necessary (when capacity is reached).

3. WHO sets the pace? (Data Flow)​

  • Pull Model.
  • You ask for pizzaList[2], it gives it to you.

4. HOW does the UI know? (Reactivity)​

  • Standard Variable.
  • Standard List<T> is completely non-reactive.
  • If you want UI reactivity later in C#, you will use a special class called ObservableCollection<T>

5. HOW LONG does it survive? (Lifecycle)​

  • Volatile. Poof! Gone when the program closes.

🗝️ Level 3: Dictionaries (The Magic Lockers)​

Sometimes, remembering the numeric index [3] or [4] is annoying. What if you could look up data using a name, a word, or an ID tag?

📜 The Top-Down Code​

using System;
using System.Collections.Generic;

public class Program
{
    public static void Main()
    {

        Dictionary<string, int> grades = new Dictionary<string, int>();
        grades.Add("John", 90);
        grades.Add("Anna", 85);
        grades.Add("Peter", 75);

        /* You can also use this syntax:
            var grades = new Dictionary<string, int>
            {
                // 2. Adding Key-Value pairs
                { "John", 90 },
                { "Anna", 85 },
                { "Peter", 75 }
            };
        */

        Console.WriteLine($"John's score is {grades["John"]}");

        grades.Remove("Peter");

        if (grades.ContainsKey("John"))
        {
            Console.WriteLine("John is still safely in the dictionary.");
        }

        Console.WriteLine("\n--- Grade Book ---");
        foreach(KeyValuePair<string, int> pair in grades)
        {
            Console.WriteLine($"{pair.Key}: {pair.Value} points");
        }
    }
}

:::🧠 The Hero's Challenge Question: In a List, you can have two identical pizzas ("Margarita", "Margarita"). Can you add "John" twice to this Dictionary (grades.Add("John", 100);)? Why or why not?

:::

🔬 The 4w2h Breakdown​

0. WHAT are we processing?​

  • Metaphor:
    • A high-school locker room.
    • The locker number (Key) maps instantly to the stuff inside (Value).
  • Definition: A generic collection of Key-Value pairs mapped by a hashing algorithm for extremely fast $O(1)$ lookups.
  • Humor: It’s like a bouncer at a VIP club.
    • If your name (Key) isn't on the list, you throw an exception.
    • If you try to register the exact same VIP name twice, the bouncer throws you out.

1. WHERE does the data live? (State & Storage)​

  • Local memory (Heap).
  • The keys are hashed to calculate memory addresses internally.

2. WHEN do we cook? (Evaluation Strategies)​

  • Eager. Values are stored and hashes are computed the moment you call. Add().

3. WHO sets the pace? (Data Flow)​

  • Pull Model.

4. HOW does the UI know?(Reactivity)​

  • Standard Variable.

5. HOW LONG does it survive? (Lifecycle)​

  • Volatile.

🏆 Boss Defeated! (Summary)​

Congratulations! You have successfully mastered the Big Three of C# memory structures.

  • Use Arrays when you know exactly how many items you have, and you need raw performance.
  • Use Lists when you have a sequence of items, but the quantity might grow or shrink over time.
  • Use Dictionaries when you need to look up data instantly using a specific key (like an ID, a name, or an email) rather than a sequential number.
